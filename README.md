# Bro Ledger .Net

**Bro Ledger .Net** 是 **[NiclasI/bro-ledger](https://github.com/NiclasI/bro-ledger)**（Java/JavaFX 版）的 C#/Avalonia 复刻版——一个只读的 _Battle Brothers_ 伴侣工具：解析你的存档文件，在游戏进行时实时展示佣兵花名册。它**从不写入存档文件**。

> 存档解析逻辑与游戏资产工具源自 9thKingOfLies 和 ScarGlamour 的 [BB-Edit](https://github.com/scarglamour/bb-edit) Electron 存档编辑器。没有这个基础，本应用无从谈起。

---

## 功能特性

### 存档数据展示

- 展示 `.sav` 存档中解析出的全部兄弟花名册
- 游戏内覆盖存档时**自动刷新**

### 兄弟总览

总览表展示所有兄弟，可按角色排序，显示全部属性、装备、特性与天赋，并提供多项增强：

- **武器品级**（开/关）：色点标记武器品级（1/2/3/命名）
- **护甲属性**（关 / 耐久 / 疲劳消耗）
- **天赋排序**（关，或按以下方式排序，字母序始终为末位平局裁决）
  - 品级
  - 共同性（当前兄弟们最常选的天赋靠左）
  - 品级 + 共同性
- **属性值**：仅当前值（天赋星始终显示于上方），或
  - 当前值 + _潜力_ 满值
  - 仅 _潜力_ 值
  - 当前值 + _期望_ 11 级属性
  - 仅 _期望_ 11 级属性

属性列与装备列可在各自类目内拖拽重排；属性列的顺序变化会同步影响兄弟详情视图的属性行排列。

#### 潜力属性

潜力 = 当前属性 + 剩余升级次数 × 平均骰值（按天赋星修正：无星近攻每级 +2，一星 +2.5，以此类推），舍入为四舍五入（halves up）。

#### 期望属性

期望属性是对最终属性的预估，取决于你在 11 级前把每次升级的属性加点分配到哪里。在兄弟详情卡片中分配。启用期望模式且加点全部分配完毕后，**点击总览中的等级单元格**可打开粘性引导面板，提示每次骰点应优先选择哪项属性；再次点击、点击应用其他位置或按 ESC 关闭。切换到其他应用（即游戏本身）时面板保持打开。

对 11 级以后的兄弟，也可以把升级后的 +1 去向记录下来，使「期望」对应到 11 级属性线，便于与其他兄弟比较。见下方 **Bro Developer**。

### 兄弟详情视图

每张兄弟卡片展示：

- **画像**、姓名、称号、出身与等级（如「佣兵，等级 4」）
- **特性与伤病**——带名称 tooltip 的图标
- **属性**——生命、决心、疲劳、主动、近攻、远攻、近防、远防；每项带天赋星
  - 数值反映游戏内实际值（基础值经特性与天赋修正）
  - 悬停被修正的属性可查看分解：基础值 + 每个特性/天赋的贡献
  - **潜力**列：按当前等级与天赋星预估的 11 级属性区间
  - **期望**列：按你计划的升级分配预估的最终属性（见 Bro Developer）
- **天赋**——全部 50 个天赋，拥有的全透明度、未拥有的 30% 透明度，带名称 tooltip
- **装备**——全部 7 个槽位（武器、盾、身甲、头盔、饰品、箭袋、囊），带属性 tooltip
- **派生属性页脚**——有效护甲值、总疲劳惩罚、武器伤害区间

### 兄弟批注（按存档持久化）

批注按兄弟的**指纹**（姓名 + 出身 + 天赋星的哈希）键控存储，因此游戏内改名会丢失其批注（改称号无碍）。星与出身在正常游戏中固定，只能通过外部存档编辑器修改。批注存储于存档同目录下的 `<存档名>.broledger.json`：

- **角色**——可从总览或兄弟卡片编辑
- **属性加点**——每项属性的计划升级分配（1–11 级），见 Bro Developer
- **11 级后加点**——11 级后已取用的每属性 +1

兄弟的手动排序（拖拽）与总览四个增强开关的状态也一并存储。

### 角色系统

角色是用户定义的分类，用于管理花名册构成并指导加点。

- 在专属的角色管理窗口中创建、重命名、编辑、删除与排序角色
- 角色顺序体现在兄弟卡片的「显示全部 / 前排 / 后排」预设按钮上
- 每个角色有**前排/后排**定位，影响总览排序
- 每个角色可按属性设置**目标阈值**与**优先级**（P1/P2/P3）：
  - P1 目标**加粗**
  - P2 目标正常字重
  - P3 目标细斜体
- 角色以稳定 UUID 标识——重命名角色会同步更新所有已引用它的兄弟
- 角色数据跨全部存档共享，存储于 `~/.bro-ledger/roles.json`

#### 角色分享

角色管理的**分享…**与**导入…**按钮可把一组精选角色发布到轻量公共存储，并生成短码供他人取用：

- **分享…**——勾选要包含的角色（默认全选），可选命名，然后发布。返回的码会显示并复制到剪贴板。
- **导入…**——粘贴码拉取角色包，再从同类勾选列表中挑选要加入的角色。码不区分大小写。导入的角色获得新 ID，重名无碍。

分享包 90 天无人取用即过期；任何一次取用都会重置时限。

这是本应用唯一的联网功能，且完全**自愿**——不点分享就不会上传任何内容，其余功能完全离线可用。码不可猜测但也不私密：存储是「按码公开」的，敏感的角色名请不要随意分享码。

### Bro Developer（期望属性）

规划兄弟的升级路径，查看贴近实际的最终属性预估：

- 兄弟卡片每个属性行有 **`[− 数量 +]` 加点编辑器**与**期望**列
- **剩余计数器**跟踪 `3 × 剩余等级` 的总加点中尚未分配的数量
- **按角色自动分配**：先填满 P1 属性（均分；超过 3 项 P1 时按字母序破平局），剩余依次级联到 P2、P3
- **偏好设置**：在**朴素**模式（始终可用、实时更新）与**贪心**模式（最优分配，需兄弟加点全部分配完毕，否则回落朴素）间切换；同时控制升级弹窗行为（见下）
  - 朴素模式：期望值 = `ceil(当前基础值 + 平均增益 × 已分配数)`，再叠加特性/天赋修正
  - 贪心模式：基于探索式算法——若两项属性都该加点，通常会选择当级骰值更高的那项

加点计划与其他按存档数据一并持久化。

### 升级通知

存档自动刷新并检测到兄弟在游戏内升级时，弹出**升级摘要弹窗**：列出每位升级的兄弟、属性增量、新增天赋，以及从批注中消耗了多少计划加点——无需手动调整即可保持计划同步。

弹窗行为可在**偏好设置**中配置：

- **常驻**（默认）——保持打开直到手动关闭
- **自动关闭**——15 秒后自动关闭
- **关闭**——完全不弹

### 快捷键

| 按键 | 位置 | 动作 |
|-----|------|------|
| Ctrl+O | 任意 | 打开存档文件 |
| Ctrl+W | 任意 | 停止文件监视 |
| Enter | 总览 | 打开选中兄弟的卡片 |
| ESC | 卡片视图 | 返回总览 |
| ESC | 升级指南弹层 | 关闭指南 |
| ESC | 任意模态（升级通知、偏好设置、角色管理） | 关闭模态 |

### 角色契合度对比

兄弟卡片支持不离开卡片的并排角色对比：

- **常驻角色列**始终显示兄弟所配角色的目标值
- 右侧始终有一个**占位列**——在下拉框中选择角色即添加一列对比；新的占位符自动出现
- 预设按钮一次填充所有可见列：**显示全部**、**前排**、**后排**、**重置**
- 可显示的列数以窗口宽度为限
- 目标值按达成度着色（绿/黄/红 = 已达成/可能达成/未达成），并按优先级样式化（粗体/正常/细斜体 = P1/P2/P3）

## 环境要求

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- Battle Brothers 游戏本体（首次启动的资产提取需要 `data/data_001.dat`）

## 构建与运行

### 开发模式运行

```powershell
dotnet run --project src/BroLedger.App
```

首次启动会显示**设置**对话框，从 Battle Brothers 安装目录提取游戏资产：指向游戏目录内的 `data/data_001.dat`，选择输出目录（默认 `~/game-art`），点击**提取**。画像、物品图标与特性图像都需要这一步。`game-art/` 目录不入库，由应用内提取器生成。

之前已提取过资产的，点击**使用现有目录**直接指向旧目录，无需重新提取。

### 发布（Native AOT 单目录自包含）

```powershell
dotnet publish src/BroLedger.App -c Release -r win-x64 -p:TreatWarningsAsErrors=true   # Windows
dotnet publish src/BroLedger.App -c Release -r linux-x64 -p:TreatWarningsAsErrors=true  # Linux
dotnet publish src/BroLedger.App -c Release -r osx-arm64 -p:TreatWarningsAsErrors=true  # macOS (Apple Silicon)
dotnet publish src/BroLedger.App -c Release -r osx-x64 -p:TreatWarningsAsErrors=true    # macOS (Intel)
```

产物在 `src/BroLedger.App/bin/Release/net10.0/<rid>/publish/`——**整个目录一起分发**（exe 依赖同目录的 Avalonia 原生库，只复制 exe 会闪退）。

推送到 GitHub 后 CI 自动产出全部 4 个 RID 的发布产物（Actions 页下载）；**推 `v*` 标签**（如 `git tag v1.0.0 && git push origin v1.0.0`）会自动构建并发布整目录压缩包（含 Avalonia 原生库）到 **Releases** 页。

### 控制台工具

```powershell
dotnet run --project src/BroLedger.Tools -- replay <save.sav|--dir <replayDir>> [transition] [output.txt]   # 重放存档快照序列
dotnet run --project src/BroLedger.Tools -- csv [output.csv]          # 按上次打开的存档导出分号 CSV
dotnet run --project src/BroLedger.Tools -- savefile <save.sav> <output.tsv>   # 导出解析段 TSV
```

## 运行测试

dotnet test

## 与 Java 版的数据互通

`.broledger.json`（按存档批注）、`~/.bro-ledger/roles.json`（角色）与 `config.json`（偏好）与 Java 版**同格式同位置**，两版工具可并存互换使用同一份数据；角色分享码两版互通（同一个云端 store）。
